## What this is

Polimiru is a static GitHub Pages site that tracks Japanese politicians' promise fulfillment. No build toolchain — HTML/CSS/JS served directly. Supabase handles likes and contact form submissions.

## Running locally

```bash
python -m http.server 8000   # serve from repo root, then open http://localhost:8000
```

## Key scripts

```bash
# Regenerate election pages + js/elections.js from data/elections.yaml
python scripts/build.py
python scripts/build.py --dry          # preview only
python scripts/build.py --id osaka_2027_governor  # single election

# Automated fact-check (updates data/politicians/*.json via Gemini 2.0 Flash)
export GEMINI_API_KEY=...   # from https://aistudio.google.com/apikey (free tier)
pip install google-genai
python tools/fact_check.py             # all politicians
python tools/fact_check.py koike       # filename substring filter
python tools/fact_check.py --dry-run   # print without saving
```

The fact-check also runs weekly via `.github/workflows/fact_check.yml` (Monday 11:00 JST). Requires `GEMINI_API_KEY` secret in GitHub repo settings.

## Architecture

### Page types and their data sources

| Page | Data source |
|---|---|
| `index.html` (home) | `js/politicians.js` — hand-curated card array |
| `politicians/{id}/index.html` | Fetches `data/politicians/{id}.json` at runtime via `js/politician-record.js` |
| `elections/{path}/index.html` | Generated by `scripts/build.py` from `data/elections.yaml`; fetches `js/data/{election_key}/index.json` at runtime |
| Candidate modal (within election pages) | Fetches `js/data/{election_key}/candidates/{id}.json` via `js/candidate-modal.js` |

### The two photo fields

A politician appears in two different data files with different field names:
- `js/politicians.js` → `photo` field (home page card)
- `data/politicians/{id}.json` → `photo_url` field (profile page hero)

Both must be updated when changing a photo.

### Promise score formula

`score = Math.round((done × 100 + started × 50) / total)`

Status values in JSON: `"実現"` (done=100), `"進行中"` (started=50), `"公約"` (pending=0), `"撤回"` (0). The `done`/`started`/`pending` count fields must be kept in sync manually with `highlights[].status`.

### CSS cascade (important)

`css/candidate-modal.css` must NOT define `.cand-card` or `.candidate-grid` layout — those belong to `css/elections.css`. The modal CSS had a duplicate section that was removed; if re-added it will break card layout.

Party color classes on `.cand-card`: `party-jimin`, `party-ishin`, `party-komei`, `party-rikken`, `party-kyosan` — applied in `partyHeaderClass()` inside each election page's inline script.

### Layout injection

`js/layout.js` injects navbar and footer HTML into every page on `DOMContentLoaded`. The note.com support URL (`https://note.com/limber_gibbon907`) appears in two places in that file.

## Data quality rules

Evidence URLs must point to official sources in priority order:
1. Government / parliament: `go.jp`, `lg.jp`, `shugiin.go.jp`, `sangiin.go.jp`, `ndl.go.jp`
2. Party official sites: `jimin.jp`, `cdp-japan.jp`, `nippon-ishin.jp`, etc.
3. News (only as a last resort; replace with official source when possible)

Status thresholds: use `"進行中"` for anything between 法案提出 and 制度施行. Upgrade to `"実現"` only when法案成立・制度開始・予算執行 is confirmed.

## Adding a new politician

1. Add entry to `js/politicians.js` (home card, `photo` field)
2. Create `data/politicians/{id}.json` (profile JSON, `photo_url` field)
3. Create `politicians/{id}/index.html` — copy an existing one, change `data-politician-id` on `<body>` and the `<title>`
4. Optionally add `election_links` in the JSON to connect to election pages

## Information source policy for Polimiru

Polimiru must prioritise accuracy and neutrality.

When adding or editing political information, always record the source.

Use only reliable sources, prioritised in this order:

1. Official government or election commission websites
2. Official politician / party websites
3. Diet, assembly, or council records
4. Official policy documents or manifestos
5. Major reputable news organisations
6. Other sources only when clearly necessary

For every factual claim, include:
- Source title
- Source URL
- Date accessed
- Brief note on what the source supports

Do not use anonymous social media posts,まとめサイト, blogs, or unsourced claims as factual evidence.

If a claim cannot be verified, mark it as:
“未確認”
or do not include it.

When sources conflict, do not choose one silently.
Write that the information differs depending on the source, and keep the wording neutral.

Do not write opinionated or promotional descriptions.
Use neutral wording such as:
- “〜と述べている”
- “〜を掲げている”
- “〜と報じられている”
- “公式サイトでは〜と記載されている”
