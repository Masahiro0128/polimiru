# 候補者発言の収集フロー

## 基本方針

全候補者について、全プラットフォームを同時に追うのではなく、争点ごとに代表発言を集める。
最初の目標は「各候補者 x 主要争点で 1 件以上の一次ソースを持つこと」。

## 収集の順序

1. 選挙公報
- 争点の初期抽出に使う
- 候補者ごとの主要スタンスの土台にする

2. 公式サイト
- 公報で不足する具体策を補う
- 政策ページ、プロフィール、ニュース欄を確認する

3. 公式 SNS
- X、YouTube、Instagram、TikTok、Facebook など
- 争点別に使える発言だけを拾う

4. 報道・討論会
- 一次ソースが薄い争点の補完に使う
- 可能なら動画や全文書き起こしへ戻る

## ワークフロー

1. 候補者ごとに監視対象 URL を確定する
2. 新しい発言を見つけたら `statements` に追記する
3. 同じ争点の根拠が 2 件以上そろったら `candidate_positions` を更新する
4. 立場が変わったら旧 stance を消さず、更新履歴を残す

## タグ設計

最低限の争点タグを固定しておく。

- `cost_of_living`
- `tax`
- `childcare`
- `housing`
- `immigration`
- `energy`
- `governance`
- `security`

必要ならあとで増やすが、最初から増やしすぎない。

## 収集時の注意

- 日付が不明な投稿は仮登録しない
- URL が切れている投稿は `needs_review` に落とす
- 断片だけでは意味が変わる場合、前後の文脈を `notes` に残す
- 同じ発言を複数媒体が転載していても、元ソース 1 件に正規化する

## 運用の最小単位

各候補者について以下を満たせば、比較ページとして最低限成立する。

- 主要争点 5 個
- 争点ごとに一次ソース 1 件以上
- 候補者ごとの総レコード 8 件以上

## 次の自動化候補

- 公式サイト URL 一覧の整備
- SNS ハンドル一覧の整備
- 発言収集用の原票 JSON を別ファイルで管理
- 手動レビュー後に公開 JSON へ反映するスクリプト作成
