# 候補者スコアリング設計書

## 目的

現行の「当選後公約追跡スコア」は当選者にしか付けられないため、有権者が**選挙前に候補者を比較できない**。
また当選後スコアが高い候補者と低い候補者で、選挙前に何が違ったかを**バックテスト**できない。

本設計では次の 2 軸を導入する。

| 軸 | タイミング | 対象 | 目的 |
|---|---|---|---|
| **選挙前スコア** (`pre_score`) | 告示〜投票日 | 全立候補者 | 有権者が選ぶ前の参考情報 |
| **当選後スコア** (`post_score`) | 就任〜次の選挙 | 当選者のみ | 現行の promise_cycles スコアと統合 |

バックテスト：`pre_score` ↔ `post_score` の相関を蓄積することで、
「選挙前にどんな候補者が約束を守ったか」のパターンを可視化する。

## データスキーマ

### 格納場所

`data/politicians/{id}.json` 内に `candidate_score` オブジェクトを追加する（`promise_cycles` と並列）。

```jsonc
{
  "id": "tsuchida-ryugo",
  ...
  "candidate_score": {
    "pre": {
      "reviewed_at": "2026-05-19",
      "election_key": "niigata_2026_governor",
      "total": 18,
      "max": 25,
      "grade": "B",
      "dimensions": [
        { "id": "specificity",   "label": "公約の具体性",     "score": 4, "note": "保育料・水道・家賃補助に数値あり。財源の詳細は未発表の項目が残る。" },
        { "id": "consistency",   "label": "政策の一貫性",     "score": 4, "note": "2026年3月表明以降、発言のブレなし。原発は「県民投票」で一貫。" },
        { "id": "track_record",  "label": "実績・経験",       "score": 2, "note": "県議1期（2023〜）。国政・首長経験なし。地方議員として3年の実績。" },
        { "id": "feasibility",   "label": "財源・実現可能性", "score": 3, "note": "水道無料化・給食費ゼロは実施例あり（他県）。財源詳細の開示が不十分。" },
        { "id": "transparency",  "label": "情報公開度",       "score": 5, "note": "公式サイトに詳細政策ページあり。公約発表会見で具体的数値を発表。" }
      ],
      "summary": "各公約に数値目標があり具体性は高い。財源の裏付けが課題。",
      "scored_by": "gemini-2.0-flash",
      "reviewed_by": null
    },
    "post": null
  }
}
```

### フィールド定義

#### `pre` / `post` 共通

| フィールド | 型 | 説明 |
|---|---|---|
| `reviewed_at` | `YYYY-MM-DD` | スコアリング実施日 |
| `election_key` | `string` | 対象選挙 ID（`niigata_2026_governor` など） |
| `total` | `number` | 5次元合計（0–25） |
| `max` | `number` | 常に `25` |
| `grade` | `"S"\|"A"\|"B"\|"C"\|"D"` | グレード（後述の変換表） |
| `dimensions` | `array` | 5次元の詳細（後述） |
| `summary` | `string` | 1〜2文の総評 |
| `scored_by` | `string` | `"gemini-2.0-flash"` / `"human"` |
| `reviewed_by` | `string\|null` | 人間レビュー者のメモ（任意） |

#### `dimensions[]`

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | `string` | 次元 ID（固定値、後述） |
| `label` | `string` | 表示名 |
| `score` | `0\|1\|2\|3\|4\|5` | 次元ごとのスコア |
| `note` | `string` | スコア根拠の1〜2文（出典・数値含む） |

## 評価ルーブリック

### グレード変換表

| total (0–25) | grade |
|---|---|
| 23–25 | S |
| 19–22 | A |
| 14–18 | B |
| 9–13 | C |
| 0–8 | D |

### 選挙前 5 次元（`pre`）

#### 1. 公約の具体性 (`specificity`)

| 点 | 基準 |
|---|---|
| 5 | 全主要公約に数値目標・達成期限が明示されている |
| 4 | 主要公約のほとんどに数値または期限がある |
| 3 | 数値あり公約と抽象公約が混在 |
| 2 | 具体的数値が一部のみ |
| 1 | 抽象的スローガンが大半 |
| 0 | 公約書・政策ページが存在しない |

#### 2. 政策の一貫性 (`consistency`)

| 点 | 基準 |
|---|---|
| 5 | 出馬表明から告示日まで立場のブレが確認されない |
| 4 | 軽微な修正はあるが核心は一貫 |
| 3 | 発言の揺れが一部メディアで報じられている |
| 2 | 過去の立場と現公約に矛盾点がある |
| 1 | 主要政策で明確な翻転がある |
| 0 | 確認不能または情報不足 |

#### 3. 実績・経験 (`track_record`)

| 点 | 基準 |
|---|---|
| 5 | 同等以上のポスト（知事・国会議員・市長など）での実績あり |
| 4 | 直接関連する公職経験あり（県議複数期・副首長など） |
| 3 | 初当選1期 or 関連分野の民間・専門職経験 |
| 2 | 公職未経験だが政策関連分野の職歴あり |
| 1 | 公職・専門職経験いずれも限定的 |
| 0 | 経歴情報の確認不能 |

#### 4. 財源・実現可能性 (`feasibility`)

| 点 | 基準 |
|---|---|
| 5 | 全主要公約に財源・実施手順が明示され、他自治体での実施例もある |
| 4 | 主要公約の財源説明あり、実施例も一部確認 |
| 3 | 財源・実施例の一方のみ確認できる |
| 2 | 財源・実施例いずれも乏しいが、制度的障壁は低い |
| 1 | 法的・財政的に実現困難な点が複数指摘されている |
| 0 | 財源・根拠が全く示されていない |

#### 5. 情報公開度 (`transparency`)

| 点 | 基準 |
|---|---|
| 5 | 詳細な政策ページ・会見動画・Q&Aが公開されている |
| 4 | 公式サイトに政策ページあり、会見でも説明 |
| 3 | 公式サイトあり、政策は概要のみ |
| 2 | SNSのみ or 公式サイトが未整備 |
| 1 | 情報がほぼ見つからない |
| 0 | 公式連絡先・サイトが存在しない |

---

### 当選後 5 次元（`post`）

※ 当選後スコアは既存の `promise_cycles` スコアを補完する。

#### 1. 公約実行率 (`fulfillment`)

| 点 | 基準 |
|---|---|
| 5 | 公約の 80% 以上を実現（`done` 分類） |
| 4 | 公約の 60–79% を実現 |
| 3 | 公約の 40–59% を実現 or 主要公約が進行中 |
| 2 | 公約の 20–39% を実現 |
| 1 | 実現は 20% 未満 |
| 0 | 公約を全く実行していない or 就任後に撤回 |

#### 2. 政策の質・成果 (`impact`)

| 点 | 基準 |
|---|---|
| 5 | 客観的指標（経済統計・人口動態など）の改善が確認できる |
| 4 | 主要政策が全国・他自治体で評価・注目されている |
| 3 | 政策の実施は確認できるが効果測定が未実施 |
| 2 | 実施はされたが効果が限定的と報じられている |
| 1 | 政策の実施が遅延または縮小されている |
| 0 | 主要政策が未実施 or 撤回 |

#### 3. 透明性・説明責任 (`accountability`)

| 点 | 基準 |
|---|---|
| 5 | 定期記者会見・議会答弁・情報公開請求への誠実な対応が確認される |
| 4 | 重要事項を適時に公表している |
| 3 | 公表は行うが遅延や不明確な説明が一部ある |
| 2 | 情報開示の消極性がメディアや議会で指摘されている |
| 1 | 情報隠蔽・虚偽答弁等が報じられている |
| 0 | 辞職・不信任・逮捕など重大事案が発生 |

#### 4. 危機対応 (`crisis`)

| 点 | 基準 |
|---|---|
| 5 | 在任中の危機（災害・事故・スキャンダル等）に迅速・適切に対応 |
| 4 | 対応に一部遅れがあったが適切に修正 |
| 3 | 危機事案なし or 評価中立 |
| 2 | 対応の遅れ・不適切さが報じられている |
| 1 | 対応の失敗が政策・住民に重大な影響を与えた |
| 0 | 危機が直接の辞任・罷免につながった |

#### 5. 将来課題への取り組み (`future`)

| 点 | 基準 |
|---|---|
| 5 | 人口減少・気候変動など長期課題に対し具体的な予算・制度を投入 |
| 4 | 長期課題への取り組みが就任期間中に目に見えて進展 |
| 3 | 計画・方針は策定されたが実行フェーズは次期以降 |
| 2 | 短期課題に集中し長期課題への取り組みが後回し |
| 1 | 長期課題が悪化している証拠がある |
| 0 | 長期課題に対する取り組みが皆無 |

## Gemini スコアリングパイプライン

### 概要

`tools/candidate_score.py` として実装する。`tools/fact_check.py` と同じく Gemini 2.0 Flash を使い、
一次情報 URL をフェッチしてスコアを半自動生成 → 人間がレビューして `data/politicians/{id}.json` に書き込む。

### 実行フロー

```
1. 対象 politician JSON を読み込む
2. 既存の promise_cycles・source_urls・official_url を収集
3. Gemini に「選挙前スコアリングプロンプト」を送信
4. Gemini が 5 次元 × score + note の JSON を返す
5. --dry-run: 結果を stdout に表示
   通常実行: candidate_score.pre を JSON に書き込む
6. human-review フラグ (--review) で reviewed_by を設定
```

### Gemini プロンプトテンプレート（選挙前）

```
あなたは日本の選挙情報を中立的に評価するアナリストです。
以下の候補者について、選挙前スコアリングルーブリックに従い 5 次元で評価してください。

## 候補者情報
{candidate_json}

## 評価ルーブリック（各次元 0–5 点）
- specificity（公約の具体性）: [ルーブリック全文]
- consistency（政策の一貫性）: [ルーブリック全文]
- track_record（実績・経験）: [ルーブリック全文]
- feasibility（財源・実現可能性）: [ルーブリック全文]
- transparency（情報公開度）: [ルーブリック全文]

## 出力形式（JSON のみ）
{
  "dimensions": [
    { "id": "specificity",  "score": <0-5>, "note": "<根拠の1〜2文>" },
    ...
  ],
  "summary": "<総評1〜2文>",
  "confidence": "high|medium|low"
}

## 注意
- Polimiru の情報源ポリシーに従い、公式サイト・政府サイト・大手報道を優先
- 政治的立場の優劣は評価せず、手続き・情報の整備状況のみを評価
- 確認できない情報は score=0 ではなく note に「確認不能」と記載し score=1 とする
```

### 実装ファイル

```
tools/candidate_score.py   # メインスクリプト
```

CLIオプション想定：

```bash
python tools/candidate_score.py                         # 全 politician
python tools/candidate_score.py tsuchida                # ID サブストリング絞り込み
python tools/candidate_score.py --election niigata_2026_governor  # 選挙絞り込み
python tools/candidate_score.py --dry-run               # JSON 保存せず stdout 表示
python tools/candidate_score.py --force                 # 既存スコアを上書き
python tools/candidate_score.py --review "masahiro"     # reviewed_by を設定
```

## UI 仕様（選挙カード）

### 表示要素

候補者カード（`.cand-card`）の既存レイアウトを維持したまま、カード下部に追加する。

```
┌─────────────────────────────┐
│ ○ [写真]                    │
│   花角 英世                  │
│   無所属（自民・公明推薦）     │
│   ── ── ── ── ── ──         │  ← 既存
│ [ 公約を見る ]               │
│                              │
│  選前  B   2022公約  69/100  │  ← 追加行
└─────────────────────────────┘
```

- **選前スコア** (`pre_score`): グレード表示 (S/A/B/C/D) + ツールチップで 5 次元内訳
- **当選後スコア**: 既存の `promise_cycles[0].score` の値をそのまま表示
- 現職（`status: "tracking"`）は両方表示、候補者（`status: "candidate"`）は選前のみ

### グレード配色

| grade | badge color |
|---|---|
| S | `#7c3aed` (purple) |
| A | `#1d4ed8` (blue) |
| B | `#0369a1` (sky) |
| C | `#b45309` (amber) |
| D | `#b91c1c` (red) |

### HTML 構造案

```html
<div class="cand-score-row">
  <span class="cand-score-pre grade-B" title="選挙前評価（公約具体性・実績など）">
    選前 <b>B</b>
  </span>
  <span class="cand-score-post" title="当選後公約実行スコア">
    公約 <b>69</b><small>/100</small>
  </span>
</div>
```

## バックテスト分析

蓄積データが 10 件以上になった時点で相関分析を行う。

### 分析テーブル設計（将来）

`js/data/score_history.json` に選挙ごとの集計を保存：

```jsonc
{
  "elections": [
    {
      "election_key": "niigata_2026_governor",
      "candidates": [
        {
          "id": "hanakado-hideyo",
          "pre_total": 20,
          "pre_grade": "A",
          "post_score": 69,
          "elected": true
        }
      ]
    }
  ]
}
```

### 仮説

1. `pre.specificity` が高い候補者は `post.fulfillment` も高い（具体的公約ほど守られる）
2. `pre.track_record` と `post.impact` の相関（経験者ほど成果を出す）
3. `pre.transparency` と `post.accountability` の相関（選前の情報公開姿勢が就任後も継続）
