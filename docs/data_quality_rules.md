# データ品質ルール

## 目的

人物カードと選挙カードを蓄積型にするため、情報の採用基準と更新単位を固定する。

## 情報源の優先順位

1. 公式一次情報
   - 選挙公報、選挙管理委員会、政党公式プロフィール、国会・自治体議事録、提出議案、採決結果
2. 本人・政党の発信
   - 公式サイト、公式SNS、記者会見、政策集
3. 報道
   - 一次情報で確認できない日付・経緯の補助に限定する

## 必須フィールド

人物カードのJSONには以下を必須とする。

- `id`
- `name`
- `party`
- `party_role` または `current_status`
- `area`
- `summary`
- `stats`
- `career`
- `source_urls`

選挙候補者JSONで人物カードが存在する場合は以下を付ける。

- `person_id`
- `profile_url`

## 達成度判定

- `完了`: 法案成立、予算措置、制度開始、条例成立など外形的に実施済み
- `着手`: 法案提出、審議開始、予算要求、検討会設置、政府・自治体方針への明記
- `一部実現`: 公約の一部のみ実施、または規模・対象が限定的
- `未着手`: 公式に確認できる実施行為がない
- `不明`: 情報不足で判定できない

判定には必ず根拠URLを付ける。根拠が報道のみの場合は、後で一次情報に置き換える。

## 更新ルール

- 選挙ページは候補者・選挙固有情報を持つ
- 人物カードは経歴、発言、公約、実績、複数選挙にまたがる履歴を持つ
- 同一人物が再出馬した場合、新しい人物カードを作らず、既存の `person_id` に紐づける
- 情報を追加したら `last_updated` 相当の日付を更新する

## 運用メモ

- 「見た目を先に作る」場合でも、空欄をごまかさず `未確認` または `情報収集中` と表示する
- 達成度は断定しすぎず、根拠の強さが弱いものは `着手` か `不明` に寄せる
- 数値スコアは算出式が確認できる状態になるまで `暫定` と明記する
